## 一、产品定位

一个**个人一体化成长/生活管理工作台**（移动端 PWA）。首页是"今天的主控台"，把时间、任务、习惯打卡、健康、账本、阅读、学习、复盘聚合到一起；所有模块的**每日数据在周报/月报中自动沉淀**，长期计划只作目标备忘、不计入每日完成率。

设计基调（从需求提炼）：
- **首页即主控台**：时间日期 + 最重要的事 + 打卡入口，一眼看到今天该做什么。
- **每日数据 → 周报/月报自动汇总**：尽量少手工填，能联动的 App 自动抓。
- **长周期计划（月/年/5 年）只备忘、不计完成**。
- **尽量复用已有 App 数据**：华为运动健康、微信读书，减少重复录入。**Microsoft To Do 按约定不接入**（个人自用优先本地）。

## 三、各模块需求详解

### 0. 首页（Home）
- 展示**时间、日期**（含星期，农历可后续补）。
- 展示**「最重要的事」**：内容来自**前一天复盘**里填的"明天最重要的事情"。
- 提供**打卡入口**（可直接在首页打卡，或跳转打卡模块）。
- （已实现外的新增：人生倒计时条、时钟等，属美化增强，非原始需求。）

### 1. 打卡（Check-in）
- 打卡项包括：**英语学习、运动指标、阅读 30min、早睡**（后续扩展低碳等）。
- 收集**每天打卡情况**（每项勾选/数值）。
- 打卡数据汇入**周报**呈现。

### 2. 任务（Tasks）
- **新增任务**：可创建待办。
- 记录**每天**的：待办总数、已完成、未完成、**完成率**；收集每天完成状况，在**周报**中呈现。
- **月计划、年度计划、5 年计划**：可输入/修改；**长时间维度的计划不计入每日完成情况**（仅作目标备忘）。

### 3. 状态（Status）
- **每日健康数据**：睡眠时间时长、今日步数、卡路里消耗、运动时长等。
- 与 **华为运动健康 App 关联获取**（一次性授权轻量拉取，避免手工录入）。
- 用**可视化图表**记录重点指标的变化。
- 在**周报**中呈现重要数据。
- **身体数据**：身高、体重，自动计算 **BMI、体脂率**。

### 4. 账本（Ledger）
- **记一笔**：区分**支出 / 收入**。
- 下方配一些**常规标签**（如餐饮/交通/购物/工资等），填**金额**和**备注**、**日期**。
- 下方来一个**月度支出/收入分布的饼状图**。

### 5. 读书（Reading）
- 将自己要读的书**添加**进来（现以微信读书书架为主）。
- 与 **微信读书 App 实现百分比阅读进度联动**（经 API Key + 代理）。
- 在工作台读完的书，可以看到自己在微信读书上**发表的点评**。
- 同时**自动记录读书时长**。
- 有**金句输入**功能（含微信读书橙色划线自动同步），也能**看历史金句**。

### 6. 学习（Learning）
- 当前背景：在做**找工作**；想做**自媒体口播**；想学**英语和韩语**。
- 这部分如何搭建**待规划**（见第六节建议）。

### 7. 复盘（Review）
- 复盘就是 **3 件事**，让我填：
  1. 今天做了什么让**未来更近**；
  2. 今天在什么事上是**及时快乐**（输入今天在**游戏上花了多长时间**）；
  3. **明天最重要的事情**是什么。
- **周末与月末**要做一个**单独的复盘**（如何构建见第六节建议）。

### 8. 过去（Past）
- 用来**存储周报、月报**情况。
- 可以**查看过去**的情况。
- 周报、月报最好可**通过 App 历史数据自动生成**，把要的总结报给我。

## 四、第三方联动点（集成清单）

| 联动对象 | 对应模块 | 获取内容 | 集成方式 |
|----------|---------|---------|----------------|
| Microsoft To Do | 任务 | 「我的一天」待办 | **按约定不接入**（个人自用优先本地，避免 OAuth 后端链路） |
| 华为运动健康 | 状态 | 睡眠/步数/卡路里/运动时长 | 华为 Health Kit，**一次性授权** + 轻量拉取（代码就绪，待用户凭证激活） |
| 微信读书 | 读书 | 阅读进度%、点评、时长、划线 | API Key + 代理（dev 用 Vite proxy；生产用 `server.js` 或 Cloudflare Worker `weread-proxy-worker.js`） |

> 说明：三个联动都涉及**账号授权与平台资质**，初期可用"手动导入/手动同步"兜底；To Do 明确不接，华为/微信读书走轻量授权/Key 方案。

## 五、数据存储与统计基线（建议）

> 以下为落地时的数据建模基线，便于周报/月报统一统计。

- **每日一条日记录**（按日期 key）：打卡项、任务完成率、复盘3问、游戏时长、各模块数值。
- **周报**：每周聚合 7 天 → 打卡达成率、任务平均完成率、健康均值、账本收支合计、读书时长合计。
- **月报**：每月聚合 → 同上 + 月度饼图数据 + 月计划完成度（仅展示，不计完成率）。
- **长周期计划**：月/年/5 年各存一份文本，不参与每日完成率计算。
- **同步**：本地以 `localStorage('zion-data-v1')` 为真值；可选经 OneDrive（`src/store/onedrive.js` + `sync.js`）做多端同步，`zion-sync-store.json` 为本地缓存。

## 六、待想清楚的部分（你的原话"帮我想想"）

### 6.1 学习模块如何搭建（建议）
按你当前的三条线拆成子模块，各自有轻量记录 + 周报沉淀：
- **找工作**：记录投递/面试/offer 状态（看板：想投/已投/面试中/offer）；复盘里可关联"今天为求职做了什么"。
- **自媒体口播**：记录"今日口播"——选题、录制时长、发布平台、播放/互动数据（初期手填，后期可接平台 API）；金句功能可复用读书的金句。
- **英语 / 韩语**：记录学习时长 + 完成的课时/单词量；可与「打卡」里的"英语学习"项打通，避免重复。
- 周报呈现：各线本周投入时长、关键进展。

### 6.2 周末 / 月末单独复盘如何构建（建议）
- **周末复盘**（每周六/日触发）：在每日3问基础上扩展——本周完成了什么、离周目标差多少、下周最重要 3 件事。
- **月末复盘**（每月最后一天触发）：月度成果、月度不足、下月重点；并关联「月计划」对比完成度。
- 实现：复用现有 `isLastDayOfMonth/isLastDayOfYear` 触发器 + Modal 弹窗，字段与每日复盘分开存储，归入「过去」。

### 6.3 周报 / 月报自动生成（建议）
- 数据源：各模块的**每日记录**（见第五节）。
- 生成时机：周末自动生成周报、月末自动生成月报（同触发器机制）。
- 呈现：结构化摘要（文字 + 关键图表）+ 存入「过去」可回看。
- 初期可用**模板拼接**（把统计数字填进固定话术）；后期可接 LLM 生成更自然的总结。

## 八、范式变更与部署说明（重要补充）

### 8.1 手动「记录日」范式（2026-07-30 起）
- **取消**原先"凌晨 6 点自动清空/滚动"逻辑，全部改为**手动驱动**：
  - 首页打卡 / 复盘 / 状态：点「保存」后才写入当天、清空输入框、记录日 +1 推进下一天。
  - 任务：点「下一天 →」推进记录日；勾选/增删即按日期存档。
  - 账本：跟随**真实时间**每分钟校准，跨零点自动跳到新的一天（不跟记录日）。
- 四个记录日（checkInDay / reviewDay / statusDay / taskDay）各自独立计数。
- 首页打卡单项勾选先存本地草稿（localStorage `zion-checkin-draft`），切界面/刷新不丢，仅「保存打卡」才入库。
- 刷新停留原页面（localStorage `zion-tab` 持久化 tab）。

### 8.2 部署
- 公网：CloudStudio 静态托管（沙箱复用，地址稳定）。
- 本地：
  ```bash
  npm install
  npm run dev        # http://localhost:5173
  npm run build      # 输出到 成品与文档/dist（先 rm -rf 旧 dist）
  npm run serve      # 4173，含微信读书/华为代理
  ```
- 微信读书纯静态需配套代理（Cloudflare Worker `weread-proxy-worker.js` 或 `npm run serve` 同 WiFi）；不填代理无法连 weread（架构限制）。
- OneDrive 同步：`src/store/onedrive.js` + `sync.js`，`zion-sync-store.json` 为本地缓存（`.gitignore` 已忽略，勿删）。
