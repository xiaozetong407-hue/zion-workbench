# 工作台 1.0.0 → 1.1.0 升级报告

> 版本：1.1.0（备份提醒 + 稳定性修复 + 代码清理）
> 日期：2026-08-19
> 状态：测试 49/49 通过，构建通过；WorkBuddy 已部署，GitHub 推送待网络恢复后补推

## 1. 发现的问题（完整体检结论）

### P0（必须马上解决）——无
数据安全架构（事务式写入、Recovery Mode、ErrorBoundary、导入回滚）与 XSS 防护（无 innerHTML/eval）经核查均健壮，未发现必须立即修复的问题。不强行制造 P0。

### P1（近期应该解决）——已全部处理
| 问题 | 说明 |
|---|---|
| ① 读函数污染内存数据 | `db.isPrompted()` 在读取时直接初始化 `load()` 返回的 cache 引用（`data.prompts = ...`），属于**未提交的脏写**，违反 P1"读函数不写数据"边界，可能污染后续提交 |
| ② 死代码堆积 | `CheckIn.jsx`（旧版 3 项打卡组件）、`TodoPanel.jsx` + `todo.js`（微软 To Do 集成，与"不集成 To Do"决策冲突）均**无任何引用**；`onedrive.js` 大部分为死逻辑（文件同步已关闭） |
| ③ 死样式残留 | 已删除模块的 16 处样式（me-overview/me-links/me-mantra 等）仍在全局 CSS，0 引用 |
| ④ 备份缺失无提示 | 数据仅存本机浏览器，用户可能长期不导出而不知道风险 |

### P2（以后可以优化）
- **组件过大**：Tasks.jsx（17 个 useState/70 内联函数）、Reading.jsx（16）、Retrospect.jsx（84 函数）——可拆分但重构风险高，1.1.0 不做
- **重复代码**：各模块重复的 id 生成模式、日期格式化工具分散在各组件——可抽公共 util
- **onedrive.js 瘦身**：文件同步已关闭但仍被 sync.js import，未来可整层移除（涉及 sync 改造，风险中等）
- **大数据量性能**：Reading 同步已用并发限流；localStorage 单 key 在多年数据后建议迁 IndexedDB（存储层已留好唯一入口，迁移只改 sync.js）
- 离线能力：SW 已具备基础（导航 NetworkFirst + 静态资源缓存），可再增强（P2）

### P3（没有必要解决）
- 花哨动效/图表库/AI 接入——不符合当前"本地优先、克制"的产品定位

## 2. 已解决的问题（本次实施）

1. **isPrompted 只读化**（db.js）：读函数不再写入 cache，消除脏写隐患
2. **删除死代码**：`CheckIn.jsx`、`TodoPanel.jsx`、`todo.js` 三个未引用文件
3. **清理死样式**：删除 16 处 0 引用的 me-* 样式
4. **新增备份提醒（1.1.0 核心功能）**：
   - 导出时记录时间（独立 localStorage key `zion-last-backup-at`，**不污染业务数据**，导出保持纯只读）
   - 「我」页数据备份区：从未导出 → 蓝色提示；超 7 天未导出 → 橙色提醒"距上次导出备份已 X 天"
   - 数据零改动：业务 blob（zion-data-v1）结构、字段、schemaVersion 全部不变

## 3. 没有修改的问题及原因

| 问题 | 原因 |
|---|---|
| Tasks/Reading/Retrospect 组件拆分 | 重构风险高、收益低，当前稳定运行；列为 P2 未来按模块小步拆分 |
| onedrive.js 整层移除 | 被 sync.js 引用，改造涉及同步层，风险中等；无实际收益（已不执行） |
| localStorage → IndexedDB | 存储层已留单入口，但迁移需测试大量数据场景；数据量未到临界，P2 再评估 |
| 微信读书代理 | 属外部依赖（已确认 workers.dev 国内不稳），方案另行讨论（腾讯云 SCF 迁移），不属本次版本 |

## 4. 新增功能

**备份提醒**（唯一新增功能，克制选择）
- 解决真实痛点：本地数据无提醒、丢失风险不可见
- 实现极简：1 个 localStorage key + Me 页提示条 + 2 段样式；零数据层结构改动
- 未做：自动备份、云同步、多设备实时同步（与"本地优先"定位冲突，未来按需再议）

## 5. 架构变化

- **数据层**：无变化（schemaVersion=1 不变、业务 blob 不变、迁移链不变）
- **新增**：独立元数据 key（备份时间，与业务数据分离）
- **移除**：3 个死文件、16 处死样式；代码净减少约 300 行
- **组件关系**：无变化（App 路由、侧栏导航、二级页机制原样）

## 6. 风险

- 低：全部改动为（a）读函数语义修正（行为不变，仅消除副作用）、（b）删除无引用文件、（c）新增纯 UI 提醒
- 已通过 49 项测试回归（含数据往返/升级模拟），验证业务数据兼容
- 待办：GitHub push 因本机到 github.com 网络中断未完成（本地提交已就绪），网络恢复后补推 main + gh-pages

## 8. 下一版本建议（1.2.0 方向，克制优先）

- **微信读书代理国产化**（若确认 SCF 方案）：解决当前国内手机核心痛点
- **组件小步拆分**：从 Reading.jsx 开始（微信读书逻辑与读书管理分离）
- **数据量监控**：localStorage 接近上限（约 5MB）时提示导出/考虑 IndexedDB
- **导出加密备份**（可选）：敏感数据打包时可选密码，提升备份文件安全性
- **不做**：账号系统、实时云同步、复杂可视化、AI 对话（保持本地优先与克制）

### 关于"现在不做什么"的结论

> 现在最不该做的是：引入账号/后端/云同步、重构稳定组件、堆新功能。
> 1.1.0 只做了四件低风险高确定性的事：一个安全修正、三处死代码清理、一个备份提醒。
> 稳定与可维护，比功能数量更重要。
