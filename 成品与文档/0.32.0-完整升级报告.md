## 3. 数据架构最终形态

```
UI 组件（15 个页面）
   │  只调用 db.* 业务方法（零直接 localStorage 业务写入）
   ▼
db.js（Repository）                    dataValidate.js（纯函数）
  - bootstrap() 安全加载+迁移视图        - validateData（类型白名单）
  - update(mutator) 深拷贝副本+事务提交   - migrateData（v1 空迁移框架）
  - exportData() 含版本/统计/完整数据     - deepClone / schemaVersionOf
  - importData() 先备份+校验+回滚
  - restoreLastBackup() / ensureSeed()
   │
   ▼
sync.js（Storage Adapter，唯一写盘点）
  - commit()：校验→序列化→写→读回验证→失败回滚+抛错
  - getCache() 损坏抛错（不再静默 {}）
   │
   ▼
localStorage['zion-data-v1']（唯一真值；schemaVersion 兼容框架，旧数据视为 v1）
```

- **启动链路**：main.jsx → ErrorBoundary → Root（bootstrap 门禁）→ 失败渲染 RecoveryScreen（导出原始/导入备份/恢复上一次备份/重试，绝不 seed）→ 成功 ensureSeed + App。
- **备份体系**：导出（含 appVersion/schemaVersion/exportTime/statistics）；导入（自动备份到 `zion-backup-last` + 校验 + 失败回滚）；「我」页与 RecoveryScreen 均可恢复上一次备份。

## 4. PWA 最终形态

- **index.html 永不预缓存**（白屏根因修复）：precache 仅 5 个 hash 静态资源（js/css/svg/ico/manifest/registerSW）。
- **导航 NetworkFirst**：`cacheName:'zion-html'`，`networkTimeoutSeconds:4`，过期 7 天；在线取新 HTML，网络失败降级最近缓存。
- **data-export / 恢复路径 denylist**：`!url.pathname.includes('data-export')` 完全绕过 SW；globIgnores 双保险。
- **保留 autoUpdate**：`skipWaiting + clientsClaim`，新版本发布后自然接管；**不 unregister、不 caches.delete、不清理用户业务数据**。
- **navigateFallback 显式关闭**：消除旧 HTML fallback 造成的 HTML/JS 版本错配窗口。
- **旧哈希残留**：`scripts/clean-stale-assets.mjs` 构建后精确清理 dist/assets 中不再被 index.html / sw.js 引用的旧文件（保留集合外删除，单文件 rm 不触发 OneDrive trash 问题）。
- 线上验证：首页 ✓、data-export.html ✓、sw.js（无 index.html / NetworkFirst+zion-html / data-export 排除 / skipWaiting+clientsClaim）✓。

## 7. 已知风险（诚实清单）

1. **旧 SW 换班需要一次加载**：已访问过旧版本的用户，首次打开由旧 SW 控制（导航已被 NetworkFirst 接管，在线立即拿新 HTML），下次加载新 SW 完全接管——过渡期无白屏（HTML 网络优先），但彻底换新需 1–2 次打开。
2. **activity 单位口径变化**：活动从「分钟当小时显示」修正为真实小时换算，历史统计口径变化（数据未改，仅展示换算）。
3. **账本/状态统计在组件内**：统计口径已用数据层+规则复算测试覆盖，但未做组件级单元测试（无测试框架，务实取舍）。
4. **`zion-backup-last` 与主数据同存 localStorage**：清站点数据会一并清除；正式导出备份仍是最稳保险。
5. **ErrorBoundary 只捕获渲染期异常**：事件回调/异步中的异常仍走 console（白屏场景已覆盖，建议日常留意控制台）。
6. **OneDrive 同步（FILE_SYNC=false）**：仍为纯本地；如需多设备同步需另行开启（含 token 配置）。
7. **`emptyOutDir:false` 保留**：配合 post-build 清理脚本，无残留问题；但 dist 目录本身不重建（对部署无影响）。
