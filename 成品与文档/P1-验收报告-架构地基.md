- **Me.jsx**：导出自动含版本信息；导入失败提示「原数据已自动保留」；新增「恢复上一次备份」。

## 3. 数据读写链路（现在长这样）

```
写路径（任意业务写入）：
  db.setXxx() / addXxx() / ...
    → db.update(mutator)
        → current = sync.getCache()（已安全加载）
        → draft = deepClone(current)        ← 独立副本，绝不直接改 cache
        → mutator(draft)                     ← 业务逻辑只在副本上执行
        → sync.commit(draft)
            → commitToStorage(draft)
                → validateData(draft)        ← 写前校验
                → JSON.stringify + JSON.parse ← 序列化自检
                → localStorage.setItem       ← 写入
                → 读回 + 再次 validateData    ← 读回验证
                → 失败：回滚旧值 + 抛错（cache 不动）
            → 成功：cache = draft + notify() ← 才提交内存视图

读路径：
  db.getXxx() → load() → sync.getCache()
    → 冷启动：loadFromStorage()（parse + validate，失败抛错 → Recovery Mode）
```

## 6. schemaVersion 如何兼容旧数据

- 无 `schemaVersion` 的数据在读取时**视为 v1**（`schemaVersionOf` 返回 1）。
- `migrateData` 当前为**空迁移**：只为内存视图补 `schemaVersion:1`（不落盘、不强制重写历史数据）。
- 迁移链框架已就位：未来 v1→v2→v3 只需在 `migrateData` 中追加 `migrateV1toV2()` 等函数；未来版本（v > 当前）数据不做降级处理。
- 本轮 10 项需求零数据结构变更，**不制造 migration**（约束 B）。

## 7. import/export 安全流程

**导出**（`db.exportData()`）：
```
{ appVersion: '0.31.0', schemaVersion: 1, exportTime: ISO 时间, statistics: {…各项计数}, data: {…完整业务数据} }
```
**导入**（`db.importData(json)`）：
```
当前数据
  → 自动备份到 zion-backup-last（原始字符串，一字不改）
  → JSON.parse（失败 → 回滚+抛错）
  → 兼容新旧格式（有 data 包装取 data，纯 blob 视为整体）
  → validateData（失败 → 回滚+抛错）
  → migrateData
  → sync.commit（校验→序列化→写→读回验证；失败 → 回滚盘上旧值 + 恢复内存 cache + 抛错）
  → 全部成功才算导入成功
```
任何一步失败：**自动恢复导入前数据与内存视图**，绝无「导入失败但原数据也没了」。

## 8. Recovery Mode 如何保证不触发 seed / 普通业务初始化

- `main.jsx` 的 `Root` 组件：先 `db.bootstrap()`。
  - **失败**（JSON 损坏 / 校验失败 / 迁移失败）→ 渲染 `<RecoveryScreen>`，**不渲染主 App、不调用 ensureSeed、不生成任何默认数据**。
  - 成功 → 才 `db.ensureSeed()`（且内部已改为副本+安全写）。
- `RecoveryScreen` 不依赖任何解析成功的业务数据（JSON 损坏时照常渲染）：
  - 【导出原始数据】直接 `localStorage.getItem('zion-data-v1')` 原样下载（不经 loadData）。
  - 【导入备份】走 `db.importData`（内部备份+校验+回滚）。
  - 【恢复上一次备份】走 `db.restoreLastBackup`。
  - 【重试】重新 bootstrap。
- `ensureSeed` 已从 db.js 模块顶层移除，模块加载不再有任何自动写入。

## 11. 新发现的潜在风险（供后续阶段注意）

1. **旧哈希资源残留**：`emptyOutDir:false` 使 dist 中旧 `index-CcsepNLT.js` 残留（无害，index.html 只引用新资源；P7 可考虑清理策略）。
2. **`isPrompted` 读方法会初始化内存 `prompts`**（既有行为，不落盘，重启无影响；已确认不违反安全边界，但未来可优化为纯读）。
3. **`sync.setCache()` 兼容壳**：已无业务调用方，仅保留防回归；若 P7 清理可移除。
4. **恢复模式只防「数据层」崩溃**：React 运行时异常仍可能导致白屏（建议 P7 后评估 ErrorBoundary，本期范围外）。
5. **`zion-backup-last` 与主数据同存 localStorage**：若用户清站点数据会一并清除（预期内；导出正式备份仍是最稳保险）。
6. **me.jsx 恢复按钮 alert 文案**：与 RecoveryScreen 文案风格统一，无功能影响。
